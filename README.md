# kilnring — 共享内存跨进程无锁环形队列

为窑炉采集场景写的 Go 库：采集进程（生产者）和控温/记录进程（消费者）跑在同一台
工控机上，通过 mmap 到同一文件的环形队列传递数据，**全程无锁**，不占用本机网络协议栈。

## 设计

```
共享内存文件（mmap MAP_SHARED）
├── 头部        魔数/版本/容量/策略/消费者数
├── 生产者行    写游标、消息计数（独占缓存行）
├── 最新记录指针 seqlock，供掉队消费者重同步
├── 消费者游标   每个独占一个缓存行（可配置不填充，用于对比伪共享）
├── 消费者信息   掉队标记、消费计数、掉队次数
├── 延迟直方图   64 个对数桶，任何进程可写
├── 异常记录环   128 条（校验错/序号断/掉队重同步）
└── 数据区      字节环：记录 = 16 字节头 {seq,len,flags} + 变长负载，16 字节对齐
```

需求对应：

1. **跨进程共享**：环形缓冲在 mmap 文件里，`ring.Create` 创建、`ring.Open` 映射，
   生产者和消费者是不同进程。
2. **序号判完整**：每条记录头带全局递增序号 `seq`。生产者先写负载、再 release 写
   `seq`；消费者 acquire 读到 `seq == 期望值` 即认为记录写完整。消费者只读
   发布游标之前的槽位（之后的内存可能还是上一圈的负载，不能当记录头解读）。
3. **缓存行填充**：写游标独占一行；消费者游标默认 stride=64 各自独占一行，
   `Create(..., padded=false)` 时 stride=8 挤在一起。`run --compare-padding`
   跑 A/B 对比（本机实测不开填充吞吐下降约 12%）。
4. **变长 + 绕回**：记录 16 字节对齐；尾部放不下时写一条 `SKIP` 标记记录
   （序号 = 绕回后那条真实记录的序号），消费者看到即跳过，不占序号。
5. **批量发布**：`ClaimBatch(lens)` 一次占多条，`Set` 写负载，`Publish` 按序
   一起发布。
6. **三种等待**：`BusyWait`（忙等）/ `YieldWait`（让出时间片）/ `SleepWait`（睡眠），
   消费者和 PolicyWait 下的生产者都可用。
7. **多消费者各自游标**：生产者覆盖槽位前检查最慢的活跃消费者游标，没读完不覆盖。
8. **掉队处理**：`PolicyWait` 等它；`PolicySkip` 把它标记为掉队（信息槽里的标志位）
   并跳过继续写。掉队消费者通过 seqlock 读"最新记录指针"重同步；读取中被覆盖
   由"拷贝后复核序号"兜住，不会把撕裂数据交给上层。

## 构建与压测

```sh
go build -o bin/ringbench ./cmd/ringbench

# 完整压测：3000 万条带序号+CRC 的消息，1 个生产者进程 + 3 个消费者进程，
# 最后一个消费者启动后睡 3 秒模拟掉队
./bin/ringbench run --messages 30000000 --consumers 3

# 边跑边看监控页（槽位占用/消费者游标/吞吐曲线/延迟分布/异常记录）
./bin/ringbench run --messages 30000000 --consumers 3 --web 127.0.0.1:8080

# 缓存行填充 A/B 对比
./bin/ringbench run --messages 20000000 --compare-padding

# wait 策略（生产者等慢消费者，一条不丢）
./bin/ringbench run --policy wait --messages 10000000

# 对已存在的共享内存文件单独开监控页
./bin/ringbench web --shm /path/to/ring.shm --addr :8080
```

压测校验项：每个正常消费者收到的消息序列完整（首条 1、末条 N、无空洞）、
顺序正确、CRC 一条不错；故意掉队的消费者被生产者标记、重同步后已收段内
顺序和校验仍然正确。全部 PASS 才退出码 0。

常用参数：`--ring` 环容量（默认 64MiB）、`--rate` 生产者限速（默认 5M 条/秒，
模拟采集进程的固定产出速率；0=不限）、`--wait busy|yield|sleep`、
`--lag-sleep` 掉队演示的睡眠时长（0=关闭）、`--padding on|off`。

## 本机实测（Apple Silicon，Go 1.26）

| 场景 | 结果 |
|---|---|
| skip 策略 3000 万条 | 全部 PASS，5M 条/秒（限速），p50 端到端 ≤ 33µs |
| 生产者极限发布 | 约 2000 万条/秒 |
| wait 策略 + 消费者睡 3s | 生产者等待，三个消费者序列全部完整 |
| 填充开/关 A/B | 8.27M vs 7.29M 条/秒，不开填充下降 11.8% |
